# Dependabot remediation review

Reviewed November 20, 2026. Baseline `419d7e0`, remediation `61ee0e8`.

## A. Executive Summary

**56 of 56 original alerts are verified against the committed lockfile.** The parent lockfile contains an affected version for every alert. The remediation lockfile retains all 14 affected packages at versions outside their recorded vulnerable ranges. A fresh lockfile-only npm audit found zero known vulnerabilities across 659 lockfile package entries, including development dependencies. GitHub's individual alert closure and Pages deployment status remain unverified.

The commit upgrades **17 remediation-related packages**: 14 named in the alerts, Express and React Router DOM as parent packages, and nanoid as an additional audit fix. Across the entire lockfile, **62 existing package paths changed versions**, including native platform variants and related updates. Five direct dependency versions changed, and four new direct development tools were added. **Zero production source files changed.** Three test files were added or removed, and three tooling configs were added.

The working tree was clean before the review. The comparison includes both manifests, the entire lockfile, source and test diffs, tooling configs, and the committed documentation and evidence. GitHub's live default branch already points to `61ee0e8`; the earlier session's “no push” statement describes its own work. The older `419d7e0` changes to the navbar, its link constants and its styles, plus initial DocuBrain setup, predate the remediation. The security snapshot and DocuBrain updates are evidence and process records. The code scanning export is an empty list and the code quality export is a 404 response. Neither establishes additional test or scan coverage. ## B. Alert Resolution Summary

**2 critical, 21 high, 30 medium and 3 low.** The alert numbers, advisory IDs, severity and range data come from the committed pre-remediation [GitHub alert export](../../dependabot-alerts.json). For each alert, this review compared every matching package entry in both lockfiles using npm semver, including nested entries, and checked all recorded advisory ranges for that package, including alternative release branches. Commas in conjunctions were normalized to spaces before evaluation. Every row had a baseline match, a replacement version and zero final matches. This verifies version-based remediation against the captured advisory data. Actual reachability and GitHub closure are separate questions.

**Resolution labels:** Direct means the root dependency was upgraded. Transitive means npm resolved the new version through the parent described in section C. Scoped override means the Firestore-specific constraint in section E selected the gRPC version. **No alert required an application source edit.** Only the gRPC rows required a dependency override.
